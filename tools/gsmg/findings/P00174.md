## Phase 174 -- OpenSSL salt bytes as bounded selectors/permutations (2026-08-08)

Phases 169-170 used each blob's eight-byte OpenSSL salt as password, hash, raw
key, matrix-summary, or XOR material. A structurally distinct proposal remained:
let the salt select and order items from already-authenticated text sources. A
repository-wide check confirmed that salt-as-index/orientation/permutation had
not previously been implemented.

First corrected the source description before testing it. The existing
`1,326`-word source is the **complete screenplay scene** from `I am the
Architect` through the Architect's `the problem is choice`, including other
speakers and stage directions. The established Architect-spoken extraction is
only 72 words (Phase 139). The exact 1,326-word sequence used by the earlier
401/400 audit was regenerated from the same screenplay PDF, frozen in
`wordlists/gsmg/matrix_architect_scene_through_choice_words.txt`, and annotated
with the source PDF's SHA-256
`2b9d43c9bb32fe85b1ed7651b095855e6ea7a25a236853d7823ea92b211d0db4`.
This keeps Phase 174 independent of the unavailable sibling PDF; older audits
that intentionally reload that PDF retain their existing environmental skip/error.

Implemented `tools/gsmg/salt_selector_permutation_audit.py` over exactly four
sources:

- DBBI's 91 characters;
- FAED's 570 characters;
- the established 31-character prime-walk selection;
- the cached 1,326-word complete screenplay scene through `choice`.

For each of the three open-blob salts plus solved Phase 3.2's salt, the audit
uses only two conventional modular-index readings (`byte % N` and
`(byte-1) % N`), forward/reversed source orientation, and original/stable
ascending/stable descending salt-byte order. This fixes the requested family at:

```text
4 salts x 4 sources x 2 index conventions x 2 orientations x 3 byte orders
  = 192 structural outputs
  = 240 exact target-bound passphrases after the word source's spaced/compact
    forms and deduplication
```

Each salt-derived passphrase was bound only to the blob that supplied its salt
and tried verbatim through the established CBC, stream, ECB, and AES-Key-Wrap
passphrase oracles. No cross-blob pooling, answer/case variants, hashing, raw-key
conversion, scalar interpretation, XOR fold, padding, offset, or extra
concatenation was allowed.

The calibration distinction is important. The known Phase 3.2 password still
opens its blob end-to-end, proving the AES oracle path. Synthetic fixtures verify
every selector indexing/orientation/order branch. But no authenticated claim says
that Phase 3.2's random salt should select its known password from any of these
four later-stage sources, so Phase 3.2 is **not** mislabeled as a known-answer
selector calibration. Its 48 structural outputs neither equal the known password
nor open the solved blob, which is recorded descriptively rather than used as a
falsification gate.

A deterministic 2,000-random-salt null was run separately for every source/rule
combination using normalized English quadgram score. The best-looking real output
was SALPH's zero-based/forward/original selection from the screenplay scene:

```text
attackedsthethethebackinaltered
uncorrected random-salt upper-tail p = 0.005497
Bonferroni across 192 inspected outputs = 1.000000
```

The minimum is almost exactly what best-of-192 inspection predicts and does not
distinguish the real salts from ordinary random bytes. Final oracle result:

```text
Phase 3.2 AES positive control:       true
structural outputs:                   192
exact target-bound passphrases:       240
known Phase 3.2 selector-passwords:   0
exact blob openings:                  0
```

**Verdict:** the specific zero-parameter salt selector/permutation family is
closed negative. The salts do not select unusually language-like material under
the two standard indexing conventions, and none of the exact outputs opens its
own blob. This does not prove that no imaginable salt-dependent program exists;
it does mean that another bit choice, chunking scheme, offset, arithmetic
operator, or cross-blob binding would introduce a new unfixed parameter and
should not be appended without a creator-backed selector.
