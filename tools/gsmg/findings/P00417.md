## Phase 417 -- blinded panel sensitivity calibration: closed `calibrated_clean` (2026-08-26)

**Question:** can the same convergence-gated external-agent panel recover a
known solved preimage when given all component values and local assembly
instructions, while the target ciphertext and plaintext remain sealed?

**Method:** The 5,022-character sealed evidence packet (`sha256
20dad195...5b58e7`) and its 6,975-character frozen prompt (`sha256
e99a9308...83ec6b`) were committed before execution. Five fresh
`general-purpose` invocations received that byte-identical prompt with
no inherited project turns, no explicit model or reasoning override, and
default service configuration. Each invocation identity was assigned
before spawning and stored in the ID-keyed ledger. Every raw response ran
through the frozen `parse_submission()`, exact Phase-416
`validate_submission_schema()`, `blinding_violations()`,
`eligible_submissions()`, `evaluate_panel()`, and `promote_candidates()`
functions before evaluation. Promoted candidates were evaluated only
under the exact Phase-410 lowercase-hex/SHA-256-EVP/AES-256-CBC profile.

**Result:** All five initial invocations were eligible: schema-valid,
`tool_used: false`, zero recorded tool calls, and blinding-clean. Each
submitted exactly one rank-1 candidate, and all five candidates were the
byte-identical 62-byte ground-truth preimage. The two-vote gate therefore
promoted exactly one candidate with 5/5 votes and best rank 1. The exact
evaluator recovered a 2,422-byte plaintext whose SHA-256 was the pinned
`b82afeb86f9e50848220f9b64b744b821400308aea273a1c949b9d2d0e408a34`.
No wrong candidate converged, so there was no spurious convergence.

**Branch:** `calibrated_clean` -- sensitivity passed and specificity was
clean in this observed panel.

**Interpretation:** the Phase-416-style panel demonstrably has
operational sensitivity for this instruction-complete solved boundary.
This does not turn the five same-environment invocations into statistically
independent observers, prove the target was physically unreachable through
the shared filesystem, or prove P32TRAILING itself is identifiable. It does
remove instrument insensitivity as the immediate reason not to run the
solution-complete comparison. The provider-side model revision was not
observable or selectable; all observable configuration fields matched the
frozen default profile. Per the stopping rule, this clean calibration
licenses drafting and separately freezing Phase 418: Phase 416's packet plus
the already-solved Phase-3.2.1 output and Phase-3.2.2 decode. It does not
license the later macro-clue experiment, which remains blocked pending that
separate comparison.
