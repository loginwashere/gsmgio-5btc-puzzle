## Phase 172 -- guide row sums as zero-parameter selectors over COSMIC's fourteen six-block strips (2026-08-08)

Phase 171 named but did not execute the most direct consumer of its new
geometry. The historical guide already supplies one row sum and one rendered
output letter for each of COSMIC's 14 six-block interior strips. Reducing those
authenticated values modulo six therefore selects exactly one surviving
16-byte block from each strip without an offset, permutation, or searched
parameter:

```text
row sums mod 6:
  [4,3,1,0,0,2,2,2,1,0,5,3,2,1]

IZLKESEEDQPPEN output codes mod 6:
  [2,1,5,4,4,0,4,4,3,4,3,3,4,1]
```

Precision correction: the second vector is **not A1Z26** despite initially
being described that way. The verified module renders each letter as
`row_sum % 26` with `A=0`, so `I` is code 8 and selects `8 % 6 = 2`.
True A1Z26 would give 3 and is not silently added as another convention.

Added this as the third consumer in `cosmic_83_guide_alignment_audit.py`.
For each of the two fixed selector streams, the audit preserves the 14 selected
blocks in order and tests only four natural reductions plus the direct stream:

- the complete 224-byte selected stream as a passphrase;
- SHA-256 of that exact ordered stream;
- XOR of all 14 selected blocks (16 bytes);
- XOR of odd and even selected strips separately, concatenated in both orders
  (two 32-byte duality forms and natural key/IV halves).

The identical selection was applied first to the first 84 blocks of the solved
Phase 3.2 ciphertext envelope and known plaintext:

**Verdict:** this was a real untested gap and is now closed negative. The
`6/84/6 -> 1/14/1` geometry remains an exact convergence, but neither of its
two already-authenticated per-strip selectors supplies the missing transition
under the minimal direct/hash/XOR/odd-even consumers. Any further operation on
the frame now needs an additional clue specifying how the six blocks interact;
the row sums alone no longer leave an untested deterministic selection rule.
