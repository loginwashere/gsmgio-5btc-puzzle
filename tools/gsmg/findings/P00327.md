## Phase 327 -- key-shape classifier (hex64/WIF/BIP39) swept against the core candidate corpus: negative, retroactively documented (2026-08-19)

**Question:** Every existing sweep decides "does this decrypt's body look
like plausible output" (printable z-score gate, or the raw 32|32-byte binary
shape `binary_key_material_backfill.py` already handles for SALPH/
P32TRAILING). None of them ask a narrower question once a body clears that
bar: does the *readable text* of a weak/strong hit actually contain a
private-key-shaped substring (a 64-hex-char scalar, a base58check WIF, or a
checksum-valid BIP39 mnemonic) that a human skim of "looks like plausible
English" would miss?

**Method:** `tools/gsmg/key_shape_classifier.py` (checksum/scalar-range-gated
finders for hex64, mainnet WIF, and BIP39-with-BIP32-derivation, all exact
matches at token boundaries -- never approximate) and
`tools/gsmg/key_shape_sweep.py` (the driver: re-runs the existing
`aes_try_open`/`aes_try_open_ecb` CBC+ECB oracle across all four blobs for
every candidate, classifies every resulting hit body, and routes any
key-shaped match through the same Bloom/API queue `binary_key_material_
backfill.py` already uses). Built and run earlier this session but never
written up as its own FINDINGS.md phase -- recorded here retroactively from
the committed checkpoint/log artifacts rather than re-running it, since the
checkpoint's fingerprint (candidate/blob/variant/classifier/driver digests)
already pins the exact run. Scope: the 648-candidate core corpus (Phase
254's exact set, digest `2d233645ef49a141`), CBC (24 variants) + ECB (12
variants) x 4 blobs = 144 operations/candidate, 14,551 expanded keystrings.

**Result:** 2,095,344 decrypt attempts. **Zero key-shape hits** -- no
`key_shape_sweep_hits.jsonl` file was ever created (the driver only creates
it on a first hit). This is a narrower question than the existing printable
z-score gate already answers over the same corpus/oracle scope (Phase-83/90/
164 territory) -- a body can pass this classifier's bar without being
printable-plausible at all (raw hex/WIF text has poor English letter-
frequency), so this is genuinely incremental coverage, not a duplicate of
prior weak/strong-hit review.

**Disposition:** rejected (this candidate universe, under this classifier).

**Facts affected:** none.

**Supersedes/corrects:** none.

**Artifacts:** `tools/gsmg/key_shape_classifier.py`;
`tools/gsmg/key_shape_sweep.py`; `tools/gsmg/key_shape_sweep_checkpoint.jsonl`;
`tools/gsmg/key_shape_sweep_run.log`.

**Reopen condition:** extending this classifier to larger corpora
(`medium_curated_all.txt`'s 66,433 candidates, matching Phase 323/326's
GPU-oracle scope) is NOT currently affordable via this Python driver -- a
timed 2,000-candidate subset did not finish in 3 minutes, projecting to
many hours for the full corpus (pure-Python AES/KDF decrypt, the same cost
problem `tools/gpu_oracle` was built to solve for the printable/structural
gate, but this classifier's hex64/WIF/BIP39 logic has not been ported to
CUDA). Reopens if that GPU port is done, or if run against a smaller
targeted corpus instead of the full medium-curated union.
