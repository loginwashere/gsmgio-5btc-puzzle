## Phase 323 -- GPU oracle backfill: medium-curated Tier 1-3 union against all 4 blobs under the AES-CBC/KDF oracle: negative (2026-08-19)

**Question:** Does the existing medium-curated candidate corpus (Tiers 1-3,
already sourced/bounded per GSMG_MEDIUM_CANDIDATE_CURATION.md) open any of
the 4 tracked blobs under the standard AES-CBC/KDF password oracle -- a
hypothesis distinct from what it has actually been tested against so far?

**Frozen inputs:** `wordlists/gsmg/medium_curated_all.txt` (66,433 base
candidates, the tracked-in-git union of Tier 1/2/3); the same 12-variant
AES-CBC/KDF scope as Phase 322 (`tools/gpu_oracle`); all 4 tracked blobs.

**Method:** Audited exactly which oracle(s) this corpus has already been
through, per blob, before running anything new (avoiding duplicate
compute/evidence): Phase 83/90's `binary_key_material_backfill.py` covered
Tier 1+2 (35,144 of the 66,433 candidates) against SALPH/P32TRAILING only,
using this project's `KDF_VARIANTS`+`EXTENDED_CIPHER_VARIANTS` AES subset --
the same 12 variants this GPU tool implements. That backfill's own scope is
explicitly SALPH/P32TRAILING; it never touched COSMIC or URLBLOB. Tier 3
(31,297 candidates) has only ever been tested under a *different* hypothesis
entirely -- Phase 164's raw-key oracle (candidate bytes used directly as the
AES key, no KDF derivation) -- never the password/KDF oracle, against any
blob. Ran the full 66,433-candidate union through `tools/gpu_oracle` against
all 4 blobs in one sweep (default `answer_forms()`/`keystr_forms()` forms,
no newline/whitespace variants, matching this corpus's own already-documented
sizing convention) rather than hand-splitting by blob, since GPU runtime cost
is low enough that the SALPH/P32TRAILING-vs-Tier-1+2 portion being redundant
doesn't justify the extra scoping complexity.

**Result:** 66,433 base candidates expanded to 588,942 passphrase forms,
swept against 48 (variant, blob) pairs (~28.3M decrypt attempts) in 3m16s.
**Zero hits** -- no weak, strong, or structural hit anywhere. Coverage
closed: COSMIC + URLBLOB for the full 66,433-candidate union (genuinely new);
SALPH + P32TRAILING for Tier 3's 31,297 candidates specifically (genuinely
new -- first password/KDF-oracle test this material has ever had); SALPH +
P32TRAILING for Tier 1+2's 35,144 candidates (confirmatory re-test under
this GPU tool, not new -- already closed by Phase 83/90 under the same
12-variant scope).

**Disposition:** rejected (this candidate universe, under this oracle scope).

**Facts affected:** none.

**Supersedes/corrects:** none.

**Artifacts:** `wordlists/gsmg/medium_curated_all.txt` (pre-existing,
unchanged); [doc/GSMG_GPU_ORACLE.md](../../../doc/GSMG_GPU_ORACLE.md) updated
with this run.

**Reopen condition:** only if Tier 1-3's own source material changes
(re-generation via `build_medium_curated_candidates.py` with new sources), or
if this candidate set is later run under the GPU tool's still-deferred
ECB/CFB/OFB/CTR/3DES/Blowfish/Camellia/SEED/Key-Wrap scope.
