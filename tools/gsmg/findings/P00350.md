## Phase 350 -- Seed 8 delta: remaining exact secret containers: negative (2026-08-20)

**Question:** do any retained plaintext bodies from the Phase 342 pilot contain
one of the exact, strongly validated Bitcoin secret-container families that
Phase 342 did not inspect? This is deliberately a delta audit, not a broad
rerun of Seed 8. Phase 342 already covered DER/ASN.1 EC and PKCS#8 private-key
structures, PSBTs, and complete Bitcoin transactions; none was reimplemented
or counted again here.

**Frozen inputs:** the identical Phase 336--338/342 sentinel corpus: 42 P0A
candidates (digest `51afdf5ce033500a`), literal and lowercase-SHA256-hex
passphrase forms, 54 existing crypto variants, four existing blobs, and the
existing CBC/ECB padding-valid plus unconditional stream-body retention rules.
The exact 12,128 retained bodies, Phase 342's whole-body/line/token scopes, and
its strict depth-one hex/Base64/gzip/zlib/ZIP decoders were reused. No
candidate, KDF, cipher, mode, blob, retention rule, scope, or decoder was
added.

**Method:** wrote `tools/gsmg/remaining_secret_container_delta_audit.py` with
exactly five new validator families:

1. BIP38: Base58Check, 39-byte payload, exact `0x0142`/`0x0143` prefixes and
   permitted flag values. Detection only; no scrypt or second password model.
2. Casascius mini private keys: exact 22/26/30-character forms, Base58
   alphabet, leading `S`, and `SHA256(key + "?")[0] == 0` check.
3. SLIP-132 Bitcoin extended keys: the 12 frozen mainnet/testnet public/private
   versions from SLIP-0132, Base58Check, exact 78-byte BIP32 structure,
   master-depth consistency, valid chain code, and valid scalar or SEC1 point.
4. Output descriptors: exact Bitcoin Core eight-character descriptor checksum
   plus a frozen bounded grammar for `pk`/`pkh`/`wpkh`/`combo`/`rawtr`,
   `sh`/`wsh`, multisig variants, key-only `tr`, and `raw`; keys accept valid
   WIF, xpub/xprv/tpub/tprv, SLIP-132, SEC1, or x-only forms with origins and
   bounded derivation suffixes. This is intentionally not a claim to reproduce
   every current Bitcoin Core descriptor/miniscript expression.
5. Complete logical Bitcoin Core records: a complete serialized key plus value
   pair for legacy `key`, checksum-bearing `ckey`, or tightly structured
   `mkey`. `key` requires a parseable secp256k1 DER private key whose derived
   public key equals the record key and whose optional Core keypair checksum is
   exact; `ckey` requires a valid public key, block-sized encrypted secret, and
   exact encrypted-secret checksum; `mkey` requires the complete method-0
   master-key fields, 48-byte encrypted key, 8-byte salt, bounded iteration
   count, and empty method-specific parameters.

Contracts were frozen from primary implementations/specifications: [BIP
38](https://github.com/bitcoin/bips/blob/master/bip-0038.mediawiki), [Casascius
Bitcoin Address Utility's `MiniKeyPair.cs`](https://github.com/casascius/Bitcoin-Address-Utility/blob/master/Model/MiniKeyPair.cs),
[SLIP-0132](https://github.com/satoshilabs/slips/blob/master/slip-0132.md), and
Bitcoin Core's [`descriptor.cpp`](https://github.com/bitcoin/bitcoin/blob/master/src/script/descriptor.cpp),
[`descriptors.md`](https://github.com/bitcoin/bitcoin/blob/master/doc/descriptors.md),
and [`walletdb.cpp`](https://github.com/bitcoin/bitcoin/blob/master/src/wallet/walletdb.cpp).
A structurally valid unrelated object was predeclared as review material only;
promotion required a scalar-bearing object to derive to the prize or Phase-331
exact target registry.

Self-test uses the official BIP38 and SLIP-132 vectors, a known Casascius mini
key, Bitcoin Core's fixed `raw(deadbeef)#89f8spxm` descriptor checksum vector,
generated-valid examples for all 12 frozen SLIP-132 versions, complete planted
`key`/`ckey`/`mkey` records, and a malformed near-negative for every family. An
end-to-end AES-CFB fixture through the real retained-body driver recovers all
five families, including a Base64-decoded Core record and a descriptor private
key related to a planted exact target. Wrong-password and 300 deterministic
length-matched random controls produce zero findings. Candidate digest and
retained-body count are enforced, and the real command additionally fails
closed unless the segment count remains Phase 342's exact 150,141.

**Result:** self-test passes. One real frozen pass inspected 12,128 bodies and
150,141 direct segments. The inherited decoders produced 22 successful hex and
16 successful Base64 outputs; 225 zlib header patterns all failed strict
inflate, and no gzip or ZIP decode succeeded. Across direct and successfully
decoded forms, the five-family registry made **750,895 validator invocations**.
Every per-format result was empty: **0 structural findings, 0 exact-target
hits**.

**Disposition:** negative for these five exact validator families on the
42-candidate sentinel corpus. This closes Seed 8's residual Phase-342 format
delta at pilot scale; it is not a full-corpus result, does not reject malformed
or unsupported descriptor dialects, and does not license checksum repair.

**Facts affected:** no puzzle fact changes. The brainstorm's Seed 8 moves from
concept-only to executed/negative with its already-covered Phase 342 formats
explicitly deduplicated.

**Supersedes/corrects:** the brainstorm ranking row's stale statement that DER
was still a Phase-338 gap; Phase 342 had already closed that gap before this
delta was run.

**Artifacts:** `tools/gsmg/remaining_secret_container_delta_audit.py`,
`tools/gsmg/remaining_secret_container_delta_report.json` (aggregate counts
and empty finding arrays only; no candidate literals or plaintext bodies).

**Reopen condition:** an authenticated clue naming one of these container
families, a parser-valid near-object that independently licenses Seed 9's
single-error repair, support for a specifically evidenced descriptor dialect
outside the frozen grammar, or a separately authorized larger candidate
corpus. Generic format expansion is not a reopen condition.
