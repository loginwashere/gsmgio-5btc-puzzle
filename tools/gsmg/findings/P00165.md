## Phase 165 -- brainstorm item 3: does anything auto-correct typos out of candidates before they reach the oracle? Closed negative, no new sweep needed (2026-08-07)

**Provenance.** Item 3 of the same 2026-08-07 in-chat brainstorm as Phase
164: *"Test typos as-written, not auto-corrected. If any candidate-
generation step normalizes spelling before hashing, a genuine creator typo
in the source text could be part of the actual passphrase and get
silently corrected away before it ever reaches the oracle."*

**Checked the premise directly rather than assuming it.** Three questions,
answered from the actual code and corpus rather than from inference:

1. **Does any candidate-generation code in this project perform spelling
   correction?** Grepped every `tools/gsmg/*.py` for spellcheck/autocorrect
   libraries and fuzzy-correction calls (`spellcheck`, `autocorrect`,
   `SpellChecker`, `textblob`, `symspell`, `Levenshtein`, `fuzzy`,
   `correct(`): **zero matches, anywhere.** The only text transforms in the
   candidate-building pipeline (`build_medium_curated_candidates.py`) are
   whitespace collapsing and an alpha-only strip (`clean_letters`), and
   both are *additive* -- `line_variants(line, include_raw=True)` always
   keeps the untouched raw line as one of its returned forms alongside the
   letters-only variant, never replaces it. `answer_forms()` in
   `cb_common.py` (used by every oracle sweep) does the same: the literal
   input string is always the first element of the set it returns.

2. **Does a genuine creator typo actually survive into a wordlist, or is
   this theoretical?** Checked with a concrete, already-known example:
   `salphation` -- the creator's own real chat misspelling of
   `SalPhaseIon` (see [doc/GSMG_STAGE_INPUT_OUTPUT_SUMMARY.md](../../../doc/GSMG_STAGE_INPUT_OUTPUT_SUMMARY.md)'s element-
   parse note) -- is present as a bare standalone token in
   `chat_mined_words.txt`, `chat_mined_lines.txt`, and (surviving into the
   curated tier) `medium_curated_tier1_primary.txt`/`medium_curated_all.
   txt`. The typo was never "fixed": it was mined and kept literally,
   exactly as item 3 hopes for. It has already gone through the nopad
   oracle at Tier-1 scale (Phase 94) and, as of Phase 164's run this
   session, the new literal-raw-key oracle at both curated and full
   Tier-1/2/3 scale -- 0 hits in every case so far (it has not yet gone
   through the padded CBC/ECB oracle at Tier-1/2/3 scale, since -- per
   Phase 163's closing note -- *nothing* has, a separate pre-existing gap,
   not specific to this candidate).

3. **Is there first-party evidence about whether typos matter at all?**
   Yes, and it's more direct than expected. Pulled the raw source message
   from the local Telegram export (`ChatExport_2026-07-26/result.json`,
   message 1806, 2020-02-22T18:11:52, sender `Jrk Bgrt` -- the creator).
   Full context: message 1793 pastes the (already-solved) Phase-3
   Architect-Choice password literally
   (`choiceisanillusioncreated...iwroteitmyself`); message 1805 remarks
   "I bet even the typo doesnt matter!"; the creator replies directly:
   *"Typos: Horrible mistakes due to rushed work. I'm 100% to blame for
   this noobish display of words. No clues to be found in those typos
   might you wonder 😉."* This is on-topic (a community member flagging a
   specific visible typo, the creator answering that exact flag), not a
   generic aside -- direct, first-party evidence against the premise's
   motivating hope, consistent with the existing `doc/
   GSMG_CREATOR_CLUE_AND_CONFIRMATION_INDEX.md` entry for this message
   ("Closes typo-mining").

**Why no new oracle script was written for this item.** Unlike items 1 and
2, there was no actual code-level gap to close -- the raw/literal form of
every mined candidate, typos included, was already flowing into every
oracle this project runs, verified concretely via `salphation` rather than
assumed from reading the pipeline code alone. Writing a sweep script would
have re-tested candidates already covered elsewhere in this project.

**Verdict:** closed negative. No candidate-generation step in this project
normalizes spelling before hashing; typo'd forms already reach every
oracle; and the creator's own on-topic statement argues directly against
typos carrying puzzle-relevant meaning. Not being pursued further absent a
new source that treats a specific typo as intentional (same bar Phase 158
already applied to `promised`).
