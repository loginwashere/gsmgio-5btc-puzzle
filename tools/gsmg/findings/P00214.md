The 2021 public walkthrough and Naddiseo's 2023 notebook decode and segment the
`matrixsumlist` instruction but define no consumer. Telegram attachment `33950`

`row_sums + col_sums`. Its intended matrix is one 1,539-character ciphertext
row (row sum `168053`), not the later selection, and it defines no output
artifact.

An earlier overlooked attachment materially sharpens the traversal history.
Messages `36612`, `36617`, and `37705` share one byte-identical 14x14 explorer
(SHA-256 `3c04f684...5bfab`). It offers ten macro traversals: two row-major, two
column-major, Z, diagonal, random, center-distance, clockwise spiral, and
counterclockwise spiral. This is provenance for a community 14x14 model, but
explicit evidence that traversal remained an interactive choice.

The strongest partial implementation is message `38470` (2025-04-20), SHA-256
`707e747a...5ee7c0`. It fixes a 14x14 counterclockwise positional spiral
starting at the top-left and calculates row/column sums of positional primes.
Messages `38468–38469` explain the author's 14x14 interest: 56 claimed readable
password letters leave 140 of 196 squares, echoing “worth one hundred fourty.”
That does not select the sum routine, and the tool's actual embedded string is
only 44 letters because `thispassword` is omitted.
Its exact outputs are:

```text

letters: ANTLGHQESHKTPG

letters: OQOJWHCJPHZ-US
```

The implementation reads only each cell's positional number. It does not read
the binary bit, color, embedded 44-letter instruction string, or the later
31-character selection. Those 28 values are therefore constants of the
numbering scheme, not a consumer result.

Denis's adjacent `matrix-animation.patch` (message `38473`) changes only three

delta audit of the accessible pre-cutoff unique histories likewise found no
