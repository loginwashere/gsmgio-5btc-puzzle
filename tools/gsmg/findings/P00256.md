## Phase 256 -- candidate-level V2 registry: core/bounded/excluded classification replaces file-level tiers (2026-08-13)

Phase 254 established that the historical 648/650-candidate corpus's
direct/bounded/thematic/mixed/control tiers are file-level and non-ordinal;
Phase 255 showed file exclusion doesn't imply candidate novelty. Both left
open a real request: classify individual *candidates*, not files, and act on
that classification -- while explicitly preserving the frozen historical
corpus so no existing sweep result's provenance changes retroactively.

**Design.** `tools/gsmg/curated_candidate_registry.py` reads (never writes)
`extended_cipher_recheck.CURATED_FILES` and the six Phase-255 menu-gap files,
and classifies all 1,213 pool candidates (the 650-candidate base pool --
648 CURATED_FILES + CORE_ALPHABET_SEEDS + VALIDATION_ANSWER + the two Phase
253 exact SEED leads -- plus the 563 Phase-255 net-new candidates) as
core/bounded/excluded. Classification is mechanical, derived from metadata
this project already recorded, not a fresh per-string editorial read:

- Generic rule: SOURCE_META's direct/control tiers -> core, bounded -> bounded,
  thematic/mixed -> excluded.
- Two sources are tagged "direct" at the file level but documented (Phase
  66/79) as mixing literal creator anchors with researcher-generated
  concatenations, so they get a per-candidate override instead: in
  `full_macro_clue_chain_candidates.txt`, only the eight literal message-8446
  fragments are core, every adjacent-pair/prefix/suffix/full-chain
  concatenation is bounded; in `yellowblueprime_matrixsumlist_variants.txt`,
  the seven pure-digit matrixsum values are core (mechanically fixed
  values), the eighteen spacing/case/order word-variant lines are bounded.
- `OPENSSL_MENU_GAP_EXACT_CANDIDATES` (SEED, IZLKESEEDQPPEN) is overridden to
  core -- exact SEED leads, not merely "bounded" -- and is now a permanent
  part of the registry's base pool rather than an opt-in-only addition.
- `CORE_ALPHABET_SEEDS`/`VALIDATION_ANSWER` are overridden to core with
  `role=("control",)` -- solved-stage precedent, kept distinct from unsolved
  passphrase candidates via the role tag rather than a separate class.
- The six Phase-255 files are classified by their existing
  `excluded_wordlist_coverage_audit.COVERAGE` handling label:
  "dedicated-audit" (Jacque Fresco, Looking Forward, SafeNet/Luna HSM --
  previously swept standalone lists) -> bounded; "medium-input"/"broad-input"
  (`content_word_filtered.txt`, both Cosmic-book files -- squashed-sentence
  concatenations or raw multi-sentence transcription, not literal shortlist
  material) -> excluded, unchanged from their pre-existing category.
- A candidate touching several sources with different classes takes the
  strongest class among them (core > bounded > excluded): an inclusion test
  ("is there a documented reason to include this candidate"), not the
  tier-ranking Phase 254's review rejected for a different purpose (a single
  synthetic "primary" descriptive label).

**Result.** 70 core, 438 bounded, 508 full (core+bounded, exact union,
disjoint by construction), 705 excluded, out of the 1,213-candidate pool.
`curated_v2_core.txt`/`curated_v2_bounded.txt`/`curated_v2_full.txt` are
generated by `--write`, never hand-edited, and registered in
`curated_candidate_corpus_audit.EXCLUDED_WORDLISTS` (`generated-output`
category) so the wordlist-manifest completeness check still passes -- the
on-disk excluded-wordlist count grows from 23 to 26 (49 total wordlists now
on disk). The historical 648-candidate corpus is untouched: digest
`2d233645ef49a141` unchanged, and none of the promoted candidates were merged
into `CURATED_FILES`.

**Promotion accounting**, comparing each candidate's V2 class against what
its old file-level tier alone implied: 167 promoted, 34 demoted, 705
rejected (excluded in both old and new terms, or newly excluded), 278
retained-only-in-the-historical-corpus (present in the 650-candidate base
pool, still excluded from V2). The 34 demotions are exactly the
`full_macro_clue_chain_candidates.txt`/`yellowblueprime_matrixsumlist_variants.txt`
concatenation lines whose file-level tier was "direct" but whose own string
is a generated combination. All figures independently re-derived from
scratch with separately-written classification/digest logic (not calling the
module's own functions) before being pinned as regression tests.

**Backfill.** The 136 net-new-to-650 candidates promoted to bounded (Fresco
55, SafeNet/Luna 62, Looking Forward 19) received a conservative consolidated
CBC rerun through `curated_v2_bounded_promotion_backfill.py`: legacy
`KDF_VARIANTS` (6) +
`EXTENDED_CIPHER_VARIANTS` (18) + `OPENSSL_MENU_GAP_CIPHER_VARIANTS` (20) =
44 CBC cipher/KDF combinations against the current 4 blobs. 136 candidates,
digest `8db6659bc547569a`, 6,327 evaluations, 1,113,552 decryptions, **zero
hits**. Phase 257's post-run history review corrects the initial rationale:
P32TRAILING was added in Phase 25, not Phase 77; Fresco and SafeNet/Luna
already had newline-aware four-blob CBC/ECB/stream/Key-Wrap coverage; and
Looking Forward had four-blob CBC/Key-Wrap coverage without newline forms.
The run remains valid but mostly repeats prior work; its useful addition is
old-family CBC over Looking Forward's newline forms. Phase 257 narrows and
closes the true remaining residual rather than rerunning all 136 again.

**Verdict:** `curated_v2_full` (508 candidates) contains every currently
known, locally available candidate this project's own recorded provenance
judges core or bounded under the documented inclusion rules above, and has
now received CBC-family coverage across every currently-supported cipher.
This is a scope claim, not a completeness claim: unavailable physical-book
paratext/gatefold pages and historical DNS TXT records could introduce new
candidates later, and "high value" remains undefined below the file/rule
level this registry operates at -- V2 replaces file-level tiers with
candidate-level, rule-derived classification, not with human judgment of
each string's individual merit. Full registry, rule table, promotion
accounting, and backfill detail:
[GSMG_V2_CANDIDATE_REGISTRY](../../../doc/GSMG_V2_CANDIDATE_REGISTRY.md).
