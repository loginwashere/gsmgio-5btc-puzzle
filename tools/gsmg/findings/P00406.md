## Phase 406 -- four structurally-anchored 256-bit windows of the full control rail: closed negative (2026-08-25)

**Question:** a fourth identified residual: `CONTROL285 = decoded[0::2]`
(285 symbols, `{B,C,D,E}`) is longer than the 236-symbol `Q472` control
rail Phase 397 already byte-packed, but 285 symbols do not themselves
divide evenly into 32-byte/256-bit units. Rather than pick an arbitrary
128-symbol sub-window, this phase restricts to the offsets independently
produced by boundaries this project has already established -- so every
admitted offset comes from existing structure, not a new free parameter.

**Method:** wrote
`tools/gsmg/phase406_control285_natural_boundary_256bit_windows_audit.py`
against a contract frozen before any code was written: four 128-symbol
windows of `CONTROL285`, each independently anchored -- offset 0
(stream-start), offset 4 (first control index after the 7-character
`BTCSEED` header), offset 49 (first control index after the stream's
unique `Z` at `decoded[97]`, which is also `Q472`'s own start), offset
157 (end-aligned, `285-128`). Offset 21 and other unspecified "grid
edges" excluded -- neither is independently selected by any
already-frozen boundary. Each window packed through Phase 397's exact 2
grid-native mappings (row-major, column-major) x 2 bit-packings
(MSB-first, LSB-first), native forward order only -- 4x2x2=16 labeled
candidates, each exactly 32 bytes. Two consumers, both reusing Phase
400's primitives verbatim: direct-scalar (reject outside `1<=k<n`,
compressed/uncompressed P2PKH) and BIP32 (raw 32 bytes directly into
`HMAC-SHA512("Bitcoin seed", seed)`, no hashing first, Phase 400's
identical six frozen derivation paths through index 999). Three planted
positives: a control-symbol-to-32-byte round trip (a SHA-256 digest
inverse-mapped through row-major/MSB-first into a synthetic 128-symbol
sequence, re-run through the real forward `pack_bits()`), plus Phase
400's own planted direct-key and BIP32-path positives reused unmodified.

**Result:** all three planted positives fire correctly. All 16
candidates reproduce as 32-byte strings, all pairwise byte-distinct
(16/16 unique); zero direct-scalar hits, zero BIP32-master hits, zero
child-address hits across 192,064 total address checks (32
direct-scalar + 32 BIP32-master + 192,000 child, 16 seeds x 6 paths x
1,000 indices x 2 encodings).

**Disposition:** closes negative per the contract's own stopping rule --
does not widen to unanchored offsets, additional windows, hashed/
reinterpreted seed material, or additional derivation paths. Per the
user's own stated plan, the next candidate is P91 repeated over Q472
(Bifid-period sensitivity), treated as a robustness audit of `BTCSEED`
rather than another key search.
