# Phase 436 — `SOURCE CODES` Referent Eligibility Audit Protocol

Frozen before implementing or running Phase 436.

## Question

Does `RETURN TO THE SOURCE CODES ... REINSERTING THE PRIME BASICS` identify a
single authenticated source object and executable prime-selection rule that is
both genuinely uncovered and sufficiently specified to license a new run?

This phase inventories referents and prior coverage. It does not generate
passwords, query a blob oracle, inspect the Phase 430 leader, or touch the GPU.

## Frozen candidate referents

The audit must include every locally or historically proposed source family:

1. Matrix film/screenplay dialogue compared with the custom monologue;
2. raw 1,539-byte Phase 3.2.1 encoded block;
3. CP1141-transcoded 1,539-letter Beaufort ciphertext;
4. decoded 1,539-letter Phase 3.2.1 answer;
5. raw 149-digit Phase 3.2.2 validation number;
6. decoded 91-letter Phase 3.2.2 answer;
7. exact Phase 3.2 parent bytes before P32;
8. first-piece/Stage-0 prime material;
9. recovered split-final-`BE` guide;
10. earlier `X2SH4Y0QB15` code/riddle;
11. repository implementation source files.

No referent may be added because its derived output looks readable.

## Frozen eligibility gates

A referent is executable only if all seven gates pass:

1. **authenticated** — exact bytes are authenticated puzzle evidence, not a
   later reconstruction artifact;
2. **locally selected** — the Architect clause or immediate page structure
   points to this object rather than merely making it imaginable;
3. **unique representation** — no equally natural raw/transcoded/decoded or
   film/screenplay representation remains;
4. **operator fixed** — prime retention, complement, walk, or another rule is
   selected rather than guessed;
5. **unit and boundary fixed** — byte/letter/word/event unit, index base,
   direction, and extent are determined;
6. **consumer fixed** — the result has an authenticated downstream consumer;
7. **genuinely uncovered** — the exact operation/material family is absent
   from prior coverage.

The audit will distinguish `covered`, `uncovered but ineligible`, and
`eligible`. An uncovered operation is not automatically authorized.

## Required live assertions

- Fresh Phase 3.2 decryption must reproduce the raw encoded block, CP1141
  ciphertext, decoded 3.2.1 answer, validation number, decoded 3.2.2 answer,
  parent-prefix boundary, and their pinned sizes/digests.
- Phase 270's exact 25-candidate/50-material inventory must be rebuilt live.
- Phase 118, 265, 268, 269, 270, 370, 418, 421, and 423 findings must exist.
- The result must explicitly identify any authenticated, uncovered raw-source
  family and list every gate it still fails.

## Frozen decision rule

- If exactly one referent passes all seven gates, stop and write a separate
  preregistration for its execution.
- If multiple referents pass, or any required representation/operator choice
  remains, classify the branch as underdetermined and make zero candidate or
  oracle calls.
- If none pass, close source identification under the currently authenticated
  evidence. Reopen only when new evidence fixes at least one failed gate.

## Explicit exclusions

- no prime-index sweep over the raw block or Beaufort ciphertext;
- no raw-vs-transcoded-vs-decoded Cartesian product;
- no reverse/complement/base variants;
- no hashing, KDF, encryption, password, Bitcoin, or blob testing;
- no treating repository analysis code as creator-authored puzzle source;
- no `AND/OR` blue/yellow extraction unless a source referent actually passes
  all gates.
