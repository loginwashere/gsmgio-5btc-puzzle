# Phase 472 — DBBI Route-Aware Plaintext Alignment Protocol

## Question

Does any route in Phase 471's complete 19,686-permutation registry align the
canonical 91-symbol DBBI stream unusually well with the authenticated
91-character Phase 3.2.2 plaintext, after charging for selection of the route
and numeric convention?

This executes item 8 of the 2026-09-02 DBBI experimental catalog. It is an
association test, not a decoder search. It will not generate or inspect
arithmetic difference strings, candidate plaintexts, passwords, hashes,
decryptions, FAED transforms, or oracle inputs.

## Frozen inputs

- `DBBI` and `VALIDATION_ANSWER` from `tools/gsmg/data.py`.
- The unique route permutations generated by Phase 471's exact registry:
  rectangle routes for both shapes, all full-period toroidal walks for both
  shapes, and all affine `n -> an+b mod 91` maps. Global permutation
  deduplication must reproduce exactly 19,686 routes.
- A fixed long normalized puzzle/Matrix passage already preserved as the first
  candidate of `phase421_invocation_3` in
  `tools/gsmg/phase421_invocation_ledger.json`. Four descriptive negative
  controls are the exact 91-character windows beginning at offsets
  `0, 273, 546, 819`. These offsets are frozen before any alignment output.
- RNG seeds `472..476`, one for the real target followed by the four controls.
- `N_NULL = 2000` position shuffles per target. Every shuffle preserves that
  target's exact residue multiset.

## Frozen score

Normalize each target to uppercase `A-Z` and require exactly 91 characters.
For every canonical DBBI route, test exactly four residue conventions:

1. DBBI `a=0..i=8` versus plaintext `A=0..Z=25 (mod 9)`;
2. DBBI `a=0..i=8` versus plaintext `A=1..Z=26 (mod 9)`;
3. reversed DBBI `a=8..i=0` versus plaintext A0Z25 mod 9;
4. reversed DBBI versus plaintext A1Z26 mod 9.

For each convention, count exact positionwise residue matches. The target's
single decision-bearing statistic is the maximum count over all
`19,686 x 4 = 78,744` route/convention combinations. Route selection and
mapping selection are therefore inside the statistic, not corrected after
the fact.

For each null draw, shuffle the target positions and recompute that complete
maximum. The upper-tail plus-one empirical p-value is:

```text
p = (1 + number(null_max >= observed_max)) / (N_NULL + 1)
```

The result file may retain the winning route metadata and the twenty highest
route/convention records for reproducibility. It must not serialize a derived
text from the alignment.

## Decision rule

A route-aware alignment lead requires all of the following:

1. real-target empirical `p < 0.001` (zero or at most the mathematically
   permitted number of null exceedances under the plus-one calculation);
2. the real target's observed maximum strictly exceeds every control's
   observed maximum;
3. the real target's empirical p-value is strictly smaller than every
   control's empirical p-value;
4. the route registry and all input invariants reproduce exactly.

Anything else is `bounded_negative`. A bar-met result is only an association
lead and requires a separately preregistered interpretation phase; it does
not license a decoder, password, FAED operation, or oracle call.

## Stop rule

- One decision-bearing execution after protocol/script hashing and lock.
- No added maps, routes, target rotations, plaintext classes, scoring

- No visual selection among near-winners.
- No password generation, hashing, decryption, Bitcoin checking, AES oracle,
  FAED use, or downstream candidate feeding.
- `G-MSL-001` is unchanged regardless of the outcome because this phase does
  not authenticate `matrixsumlist` as the operator or bind the plaintext as
