# Phase 491 raw-histogram-only calibration repair

Date: 2026-09-13
Status: development protocol; generator rules frozen before GPU screening

## Correction being tested

In Model B the witnessed FAED stream is a columnar permutation of the hidden
checkerboard digit stream. Character counts and total length survive that
permutation, but checkerboard segmentation does not. Phases 484X and 487--490
forced FAED's witnessed `{g,i}` segmentation (436 tokens, 302 singles, and all
25 token counts) onto the hidden side of their synthetic fixtures. Their
search-mechanism results remain valid for that constructed subfamily, but the
claim that it represents FAED's exact Model-B marginal profile is withdrawn.

This phase fixes calibration representativeness. It does not change the
dual-lane search architecture and does not strengthen the evidence that
`{g,i}` is the true escape pair.

## Frozen generator

- Pair `{g,i}`, raw length 570, and the nine raw-symbol counts
  `(54,49,52,49,69,57,107,58,75)` are the only FAED-derived constraints.
- A latent feasible code-count profile is generated by deterministically
  shuffling a canonical string having that multiset and taking the first
  shuffle that segments without a dangling escape. FAED's witnessed order is
  never used. Latent token count, single count, and all 25 code counts are
  outputs, not targets.
- The board family is the historical `vic_profile` family: the seven most
  frequent letters in the closed training corpus occupy the seven single
  slots. Within the single and double partitions, passage letter counts and
  sampled code counts are paired in descending-frequency order. This is the
  exact minimum-L1 assignment inside those two partitions; it does not refer
  to the Phase-484X target token histogram.
- Each fixture index owns one of twenty non-overlapping source regions. Its
  entire passage must fit inside that region and is the word-boundary passage
  requiring the fewest letter-count edits, with source offset as the
  deterministic tie-break.
- Required edits are applied greedily. At each step the replacement giving
  the largest exact local quadgram-score change is chosen; position and new
  letter break ties. This changes the minimum number of characters needed to
  reach the sampled latent code counts.
- Column orders use an independent PCG32 seed. Development and holdout corpus
  splits remain separate.
- Every fixture must round-trip, reproduce all nine raw counts exactly, have
  a unique latent-profile digest within the requested batch, edit no more than
  18% of its source passage, and score at least -4.70 per quadgram. Observed
  segmentation is recorded only as a diagnostic.

The edit ceiling was set after a CPU-only structural generation of all twenty
development profiles and before any recovery/GPU screen. Region containment
produced a maximum minimum-edit fraction of 17.9%; all twenty edited passages
scored between -4.51 and -4.15 per quadgram. The ceiling is a corruption guard,
while the quadgram threshold is the substantive language-quality guard.

## Development decision sequence

1. Generate and structurally verify ten development fixtures, indices 0--9.
2. Run only the Phase-490 front stage on those fixtures. This costs roughly
   five minutes per fixture and measures whether at least one true depth-7
   fragment survives; no full solver and no FAED run occurs here.
3. If fewer than 8/10 retain truth at refined depth 7, retrain the invariant
   prefix models on raw-histogram-only fixtures and repeat once on disjoint
   development indices 10--19.
4. If the front gate reaches at least 8/10, run the unchanged complete solver
   on three hard retained fixtures. Require exact top-1 recovery on at least
   two of three before considering a new separately locked real run.

The thresholds are calibration gates, not statistical claims. No holdout is
spent in this development repair. A failure is evidence about this generator
and solver pairing only.
