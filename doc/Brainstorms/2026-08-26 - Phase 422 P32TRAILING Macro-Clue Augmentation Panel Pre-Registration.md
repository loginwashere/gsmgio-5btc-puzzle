# Phase 422 — P32TRAILING Macro-Clue Augmentation Panel Pre-Registration

> [!caution] Frozen before implementation; no panel execution authorized
> Phase 421 closed `novel_convergence_negative`, completing the calibrated
> solution-complete comparison. This document defines the separately controlled
> macro-clue condition that Phases 416-421 deliberately deferred. Implementation
> and frozen artifacts must be committed separately, and a later explicit user
> authorization is required before any Phase 422 solver invocation.

## Question

When the working Phase 421 sealed-target panel receives the same complete
Phase-3.2 evidence plus the authenticated creator macro clue and the project's
bounded, accurately labeled macro-chain state, do at least two of five fresh
solvers converge on an exact candidate preimage not present in the frozen prior-
evaluation comparator, and does that candidate open P32TRAILING under the same
redacted oracle?

This is a candidate-generation experiment, not a claim that the macro clue is a
password, a strict program, or specifically attached to P32TRAILING.

## Why this condition is now admissible

Phase 416's surface packet was negative but omitted already-solved nested
outputs. Phase 417 established that the panel can recover a held-out solved
boundary. Phase 421 then delivered Phase 418's solution-complete packet through
a working one-file bootstrap and closed `novel_convergence_negative`: eight new
promotions all tested negative. There was no terminal or structural hit, so no
confirmation phase blocks this comparison.

The macro clue is the strongest creator-authored cross-stage artifact not shown
to the baseline panel. Adding it now creates a controlled augmentation against
Phase 421 rather than silently mixing it into the baseline.

## Frozen prior-evaluation comparator

Before any solver launch, implementation must rebuild and commit only digests,
counts, and provenance for the union of these exact candidate-byte sets:

1. Phase 270's 50 material values;
2. the eight genuinely new Phase 421 promotions that actually received oracle
   calls; and
3. every exact passphrase/preimage form actually tested for the Phase 322 and
   Phase 334 1-8-fragment macro-permutation corpora under the Phase 422 target
   profile, regenerated through the original generators and form functions.

The implementation must pin each component count and digest, the union count
and digest, and prove that all eight Phase 421 evaluation digests resolve to the
expected replay bytes. Phase 421 singletons and non-promoted candidates are not
duplicates merely because they were proposed: if they newly converge, they are
eligible for evaluation.

Each promotion is classified as either
`exact_duplicate_in_frozen_comparator` or
`not_in_frozen_comparator`. The latter wording is deliberate: this bounded
comparator does not claim to index every candidate ever tested anywhere in the
project. A candidate absent from it may still overlap an older unrelated audit;
that residual archival limitation must be reported, not hidden.

An exact comparator duplicate receives no repeated oracle call. The solver-
visible scope note must not disclose candidate strings, hashes, counts, or
which prior phase tested a value.

## Prompt delivery and eligibility

The implementation must render one committed solver prompt and a short launcher
permitting exactly one escalated `sed` read of that prompt. The command,
absolute working directory, `sandbox_permissions: require_escalated`, fixed
justification, no-prefix-rule constraint, and one-file/no-other-tool instruction
are inherited from Phase 421 except for the Phase 422 prompt path and a line
range mechanically proven to cover the complete file.

Every fresh invocation receives byte-identical launcher bytes. Eligible records
must self-report `bootstrap_read_used: true` and `other_tool_used: false`. If
tool telemetry is unavailable, compliance remains self-attested and the result
must say so. Escalation is not filesystem isolation.

No malformed response is repaired or reused. Invocation IDs are assigned before
launch. Launch only enough IDs to obtain five eligible submissions; never
exceed eight. Any concurrently launched response beyond the first five eligible
records must be transparently retained as non-voting and excluded from all
promotion and evaluation logic.

## Outcomes and stopping rule

Branches are evaluated in this order:

1. **`protocol_invalid`** — fewer than five eligible submissions within eight
   IDs, any artifact/configuration/comparator drift, or another frozen invariant
   fails. No puzzle inference follows.
2. **`terminal_hit`** — the first evaluated comparison-new promotion reaches
   Phase 416's address-confirmed terminal condition. Stop and independently
   confirm under a new protocol before any prize action.
3. **`structural_hit`** — no terminal hit, but the first evaluated comparison-
   new promotion fires a frozen structural tier. Stop and preregister a
   confirmation phase.
4. **`comparison_new_convergence_negative`** — at least one promoted candidate
   is absent from the frozen comparator, all such evaluated promotions are
   negative, and no hit occurs.
5. **`duplicate_only_convergence`** — promotions occur, but every promotion is
   an exact frozen-comparator duplicate. Zero oracle calls occur.
6. **`no_convergence`** — no exact candidate receives two votes. Zero oracle
   calls occur.

Promotions and comparison-new evaluations use the inherited deterministic vote,
best-rank, length, and SHA-256 ordering. Evaluation stops at the first terminal
or structural hit; otherwise every comparison-new promotion is evaluated.

## Interpretation limits

A negative Phase 422 result would close only this calibrated macro-augmented
panel condition. It would not prove P32TRAILING unidentifiable, prove the macro
clue unrelated, reject parked macro checkpoints, or exhaust arbitrary
non-concatenation operations. Convergence is reproducibility within a
same-provider panel, not statistical independence. The prompt exposes the
macro state and can induce correlated framing. Target secrecy remains an
instruction-level boundary because agents share a filesystem and independent
tool telemetry may be absent.
