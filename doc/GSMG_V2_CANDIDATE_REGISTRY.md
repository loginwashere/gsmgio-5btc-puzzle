# GSMG V2 Candidate Registry

Candidate-level classification, replacing the historical corpus's file-level
direct/bounded/thematic/mixed/control tiers with a per-candidate core/bounded/
excluded class. The historical 648/650-candidate corpus is **read, never
written** by this registry -- its digest (`2d233645ef49a141` / 648,
`ab8252005a8388f5` / 650) is unchanged and no promoted candidate was merged
into `extended_cipher_recheck.CURATED_FILES`.

## What this is and is not

**Is:** a mechanical reclassification of every candidate this project has
already produced (the 650-candidate base pool plus Phase 255's 563 net-new
candidates), using rules derived from metadata this project already recorded
-- not a fresh per-string editorial read, and not a claim that every
possible high-value candidate is now accounted for.

**Is not:** a replacement for the historical corpus (which stays frozen for
backward-compatible sweep provenance), a claim that unavailable material
(physical-book gatefold, historical DNS TXT) has been considered, or a
re-introduction of the single ordinal "primary tier" ranking Phase 254's
review rejected. A candidate's class is the *strongest* class among all its
sources (core > bounded > excluded) -- an inclusion test, not a rank.

## Classification rules

| Old signal | V2 class | Notes |
|---|---|---|
| `SOURCE_META` tier `direct` or `control` | core | generic rule |
| `SOURCE_META` tier `bounded` | bounded | generic rule |
| `SOURCE_META` tier `thematic` or `mixed` | excluded | generic rule |
| `full_macro_clue_chain_candidates.txt`, candidate is one of the 8 literal message-8446 fragments | core | per-candidate override (Phase 79) |
| `full_macro_clue_chain_candidates.txt`, any other line (pair/prefix/suffix/full chain) | bounded | generated concatenation, not literal |
| `yellowblueprime_matrixsumlist_variants.txt`, pure-digit matrixsum value | core | mechanically fixed value |
| `yellowblueprime_matrixsumlist_variants.txt`, spacing/case/order word-variant | bounded | generated concatenation, not literal |
| `OPENSSL_MENU_GAP_EXACT_CANDIDATES` (SEED, IZLKESEEDQPPEN) | core | exact SEED leads, now permanent (not opt-in) |
| `CORE_ALPHABET_SEEDS` / `VALIDATION_ANSWER` | core, `role=("control",)` | solved-stage precedent, tagged not classed separately |
| Phase-255 file, `COVERAGE` label "dedicated-audit" (Fresco/Looking Forward/SafeNet-Luna) | bounded | previously swept standalone lists |
| Phase-255 file, `COVERAGE` label "medium-input"/"broad-input" (content-word-filtered, both Cosmic-book files) | excluded | squashed/raw derived text, unchanged from pre-existing category |

## Promotion accounting

Comparing each candidate's V2 class against what its old file-level tier
alone would have implied:

```
promoted:                     167
demoted:                      34
rejected (final class excluded): 705
retained (historical-corpus-only, still excluded from V2): 278

transitions:
  bounded  -> bounded   243
  bounded  -> core      2      (the two exact SEED leads)
  core     -> bounded   34     (macro-chain/yellowblueprime concatenations)
  core     -> core      64
  excluded -> bounded   161    (25 multi-source base-pool + 136 Phase-255 net-new)
  excluded -> core      4      (multi-source base-pool candidates)
  excluded -> excluded  705    (rejected)
```

The 34 demotions are exactly the two overridden sources' generated-
concatenation lines: a file-level "direct" tier does not make every line in
that file literal, and the registry's per-candidate override corrects that
specifically rather than reinterpreting the file's other, genuinely literal
content.

## Backfill: CBC-cipher-family coverage for the 136 net-new bounded candidates

The 136 candidates promoted to bounded from outside the base 650 (Fresco 55,
SafeNet/Luna HSM 62, Looking Forward 19) already had dedicated-audit coverage
from Phases 88-90/116/44 respectively -- but those phases predate this
project's current 4-blob default (`P32TRAILING` added Phase 77, `URLBLOB`
promoted to default Phase 192), and Phase 192 explicitly declined to silently
re-run every historical dedicated-audit corpus after that promotion.
`curated_v2_bounded_promotion_backfill.py` closes the CBC-cipher-family part
of that gap:

```
python3 tools/gsmg/curated_v2_bounded_promotion_backfill.py --self-test
python3 tools/gsmg/curated_v2_bounded_promotion_backfill.py --run
```

**Explicitly out of scope for this backfill:** stream ciphers (AES-CFB/OFB/

blobs. Phase 255's Blowfish/Camellia/SEED family already covers all 625
menu-gap candidates (including these 136) against the current 4 blobs, so
that specific family is not re-listed as a gap.

## Judgment

`curated_v2_full` (508 candidates) contains every currently known, locally
available candidate this project's own recorded provenance judges core or
bounded under the documented rules above, and now has CBC-family coverage
across every currently-supported cipher. This is a scope claim bounded by
what this registry actually classified, not a completeness claim over the
whole universe of possible candidates: unavailable physical-book paratext/
gatefold pages and historical DNS TXT records could introduce new candidates
later, and "high value" is still undefined below the rule level this
registry operates at.
