## Objective

Identify the concrete artifact or state meant by the creator's repeated
`ying yang`/`yinyang` clue without using AES success, arbitrary transforms, or
post-hoc wordplay to select it.

The creator-grounded sequence is:

```text
yellowblueprimes
-> matrixsumlist
-> lastwordsbeforearchichoice
-> yinyang
-> wewontgiveawaythepassword
-> itsinfrontofyoureyesbutyourenotseeingit
-> verylaststepisatruegiveaway
-> promised
```

The search target is therefore a **recognizable next-phase artifact**, not the
literal password `yinyang`.

## Evidence Constraints

An artifact can be promoted only if it satisfies all four core constraints:

1. **Primary provenance** -- it exists in authenticated puzzle bytes, an
   authenticated solved plaintext, or creator-authored media/text.
2. **Visible or already present** -- it fits the creator-confirmed
   `in front of your eyes` wording without first requiring an unselected
   decryption or a broad search.
3. **Genuine dual structure** -- it contains two opposed/complementary parts
   and a fixed relationship or center. Merely containing two objects is not
   enough.
4. **Correct transition position** -- it occurs at, or is mechanically
   produced immediately after,
   `matrixsumlist -> lastwordsbeforearchichoice`.

Promotion also requires at least one independent discriminator:

- a creator response specifically tied to that artifact;
- a deterministic operation leading to a known page, lock, or output shape;
- a rare structural property that survives a matched null/control family.

Literal AES success is a confirmation after promotion, never a selector.

Only artifacts satisfying the four core constraints proceed.

For each, test a separate, closed mechanic family declared before output:

### `BUT/HYE`

- exact two-row alignment;
- exact column pairs;
- native `a-i` filtering already fixed by the source;

### Selected/Complement

- literal substrings;
- same-position pair classification;
- transitions where selected and complement differ;

### Paired Page Objects

Do not test cross-password candidates again.

## Phase 4: Matched Controls

Every apparently meaningful relation needs a matched control:

- compare rail relations against all same-length beginning/end triples in the
  frozen Architect source;
- compare selected/complement relations against masks with the same 31/60
  profile;
- compare page-pair layout properties against the other authenticated GSMG
  pages and textarea pairs;
- use the first-piece polarity as a positive control for whether the audit can
  recognize a real, intentional dual construction.

If the statistic is selected after viewing the real output, rerun the complete
declared family or report it as descriptive only.

## Phase 5: Promotion and Stop Rules

Promote an artifact only when:

1. all four core constraints pass;
2. one independent discriminator passes;
3. exactly one local operation survives;
4. the operation yields a concrete next object, lock, route, or output shape.

Then, and only then:

- test exact raw/SHA/newline forms if the operation explicitly produces a
  passphrase;
- test a route only if the operation explicitly produces route syntax;
- test private-key/address material only if the operation explicitly produces
  32-byte or WIF-shaped data.

Stop the branch when:

- no artifact clears all mandatory constraints;
- multiple artifacts remain tied without new primary evidence;
- the next move requires choosing among arbitrary transforms;
- the only validation is an oracle hit search over many candidates.

## Recommended Execution Order

1. Build the assertion-backed inventory.
2. Complete the qualification table before rendering new combinations.
3. Audit `BUT/HYE` first because it is transition-adjacent.
4. Audit paired page objects second because they best fit “in front of your
   eyes.”
5. Audit selected/complement text third.
6. Use the first-piece construction only as a positive/control artifact.
7. Leave the book, community guide pair, and hypothetical SALPH halves
   evidence-gated unless the first three point to them.

The intended deliverable is not another candidate wordlist. It is either:

- one uniquely justified artifact plus one deterministic next operation; or
- a rigorous statement that no retained artifact currently satisfies the
  creator's full description, making new primary evidence necessary.
