# First-Piece `Ce/Fe` and Checkerboard-Seed Gate Audit

## Scope

This audit tests two linked brainstorm claims:

1. interpret the composited `CECECE` logo gray and explicit `FEFEFE` rabbit
   marker as `Ce=58` and `Fe=26`, then apply difference/half/sum-list arithmetic;
2. concatenate the wider element inventory and use first-occurrence
   deduplication plus an unused-letter tail to construct a DBBI/FAED board.

The arithmetic and all bounded construction families are reproduced before
the source and selection gates are judged. No checkerboard decode, password,
or cryptographic oracle is run.

## `Ce/Fe` arithmetic

Title-casing the proposed collapsed bytes gives valid symbols:

```text
Ce = 58
Fe = 26
```

The proposed operations reproduce exactly:

```text
Ce - Fe                = 32
[Ce+Fe, Ce, Fe]        = [84,58,26]
half of that sum-list  = [42,29,13]
29 and 13              = prime
42                     = 29+13
```

The last equality is forced: halving the additive list `[84,58,26]`
necessarily preserves its checksum. It is not independent Matrix evidence.

Two further role matches are exact:

```text
secp256k1 scalar width                         = 32 bytes
574061                                        = 0x08C26D = 3 minimal bytes
zero bytes needed for a 32-byte serialization = 29 = Ce/2
len("matrixsumlist")                          = 13 = Fe/2
```

These give the halves concrete roles, but only after choosing to serialize the
first-piece prime as a private scalar. No authenticated instruction currently
selects that role.

The byte operation from Point 19 also reproduces:

```text
0xFE - 0xCE = 0x30
0xFE XOR 0xCE = 0x30 = ASCII "0"
```

This counts once, not twice. All set bits of `CE` are contained in `FE`, so
subtraction without borrow and XOR are forced to agree.

## The decisive source-provenance problem

The `CE` gray is not present in the original 48×48 RGBA favicon. It appears as
one 3×3 block only after the favicon is enlarged and alpha-composited onto the
page background:

```text
source favicon CE pixels:  0
rendered/captured CE pixels: 9
```

It is also one member of a ten-byte family of single-3×3 rendered logo grays:

```text
CE D3 D5 DB DF E1 EC ED F1 F2
```

Only `CE -> Ce` and `DB -> Db` title-case into element symbols. Requiring an
even atomic number leaves Ce, but that requirement is learned from the desired
halving arithmetic rather than supplied independently. Thus the arithmetic can
rank render grays after the fact; it does not establish CE as authored input.

## Proposed element seed

Using the brainstorm's native fragment order:

```text
BaTcH | OCBeHe | CeFe | PHV
```

gives:

```text
concatenation:          BaTcHOCBeHeCeFePHV
uppercase first-dedupe: BATCHOEFPV
```

The fragment support is uneven:

- `OCBe` is an exact row-local G-shadow consumer.
- `PH -> V` is an exact Phase-97 recognition transition.
- `BaTcH` is exact but failed its Phase-205 execution gate.
- `He` requires filtering `HYE` and unselected chemical case promotion.
- `Ce` is a render-generated gray and is not independently selected.

All 24 fragment orders produce 24 distinct deduped seeds. Combining those
with the already-declared 26 dropped-letter choices, three tail presets, and
two merge directions gives:

```text
parameter rows: 24 × 26 × 3 × 2 = 3,744
unique 25-letter boards:              2,430
```

Even after fixing the proposed fragment order, 156 parameter rows remain and
produce 105 distinct boards. The conventional `J`-drop, forward-tail,
backward-merge choice gives:

```text
BATCHOEFPVDGIKLMNQRSUWXYZ
```

but none of those three choices is selected. More importantly, the known-real
Phase-3.2 checkerboard demonstrates that its unused tail was hand ordered, not
generated by a reusable formula. With this ten-letter seed and a fixed J drop,
there are `15! = 1,307,674,368,000` possible unused-letter tails alone.

## Verdict

Retain the exact `[84,58,26] -> [42,29,13]` arithmetic and the `29`/`13` role
matches as a compact recognition hypothesis. Close Point 16 as a data source:
its CE operand is produced by rendering rather than authored in the favicon,
and its consumer operations are unselected.

Close Point 18. The proposed fragments yield a reproducible seed string, but
not a checkerboard alphabet; the family remains enormous precisely where the
known Phase-3.2 construction provides no reusable tail rule. Reopen only with
an authenticated CE selector or native CE artifact and an explicit fragment,
deduplication, missing-letter, tail-order, and board-layout instruction.
